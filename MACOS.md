# Aeternia DNS Switcher 2.2.0 — macOS

## Установка поверх старой версии

1. Закройте Aeternia DNS.
2. Распакуйте архив этой версии и откройте Терминал в его папке.
3. Если DNS-движок ещё не установлен: `brew install dnscrypt-proxy` (без sudo).
4. Выполните `sudo bash install.sh`, введите пароль администратора.
5. Откройте `/Applications/Aeternia DNS.app` или выполните `aeternia-dns-switcher` без sudo.

Вместо архива можно использовать единый файл:

```bash
sudo bash aeternia-dns-installer.sh
```

Нужны Apple Command Line Tools с системным `/usr/bin/python3` версии 3.9+,
Homebrew и установленный `dnscrypt-proxy`. Установщик использует системный
Python с `-I -S`: пользовательские модули Python не загружаются с правами root.
При отсутствии Command Line Tools выполните `xcode-select --install`.

При обычном открытии и выборе страны/«Без прокси» пароль не запрашивается.
Правило привязано к учётной записи, запустившей установку; для другого пользователя
потребуется отдельная настройка. Повторная установка этой сборки заменяет правило
на пользователя, который её запускает.

## Логика «Без прокси»

- Перед первым включением сохраняются исходные ручные IPv4/IPv6 DNS либо режим DHCP.
- Переключение страны не перезаписывает исходные DNS адресом 127.0.0.1.
- Если приложение использовали с несколькими подключениями, сохраняются все затронутые подключения.
- «Без прокси» восстанавливает их настройки и проверяет результат через `networksetup`.
- Сбрасывается DNS-кэш macOS и перечитываются настройки `mDNSResponder`.
- Только после этого выгружается служба. Перезагрузка Mac не требуется.
- Если команда завершилась ошибкой, журнал сохраняется; операцию можно повторить.
- Если пользователь/другая программа уже задали новые внешние DNS, эти изменения сохраняются.
- Последующая проверка системного DNS отдельно сообщает, если DNS роутера/провайдера недоступен.
  Успешное восстановление настроек само по себе не означает, что провайдер доступен.

Для определения подключения используются названия **сетевых служб**, а не аппаратных
портов. Переименование учитывается по сетевому интерфейсу, если соответствие однозначно.
Если маршрут проходит через VPN и нельзя определить физическое подключение, включение
отклоняется с пояснением. Отключение не зависит от наличия маршрута по умолчанию.

Перед перенаправлением на локальный DNS помощник проверяет конфигурацию, запуск и
ответ выбранного Aeternia-сервера. При ошибке он пытается восстановить предыдущий сервер
либо исходные DNS. Клавиша B использует ту же процедуру, а не простое копирование TOML.

## Переход с 2.1.3 и более ранних версий

Старые версии не сохраняли исходные системные DNS. Восстановить утраченные ручные
адреса автоматически невозможно. Если обнаружены файлы старой Aeternia и локальный
DNS, установщик убирает loopback-адреса, сохраняет остальные DNS в списке либо включает
DHCP, затем останавливает старую системную Homebrew-службу. Об этом выводится предупреждение.
Новая версия начинает сохранять точные исходные настройки со своего первого включения.

Старый Homebrew TOML и его `.bak.*` остаются на месте для ручного восстановления.
Новая версия использует отдельный конфиг и не изменяет их. Homebrew, Python и certifi
не удаляются. Серверы из `/var/root/.config/aeternia-dns/servers.json` по возможности
переносятся в `~/Library/Application Support/Aeternia DNS/servers.json`;
при отсутствии доступа установщик сообщает об этом. Также поддерживается перенос из
старого `~/.config/aeternia-dns/servers.json`.

Если порт `127.0.0.1:53` занят другой службой, включение отменяется. Если это оставшаяся
пользовательская Homebrew-служба от старой установки, после восстановления DNS остановите
её обычной командой `brew services stop dnscrypt-proxy`, затем повторите включение.

Если интернета нет ещё до установки, сначала восстановите DNS текущего подключения:

```bash
networksetup -listallnetworkservices
sudo networksetup -setdnsservers "Wi-Fi" empty
sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder
```

Замените `Wi-Fi` точным названием из списка. Если до Aeternia использовались ручные DNS,
вместо `empty` укажите их. Эти команды не требуют скачивания файлов.

## Права доступа и файлы

| Назначение | Путь |
| --- | --- |
| Ограниченная точка входа | `/Library/PrivilegedHelperTools/space.aeternia.dns-helper` |
| Код и копия DNS-движка | `/Library/PrivilegedHelperTools/space.aeternia.dns/` |
| Журнал исходных DNS, конфиг, логи | `/private/var/db/space.aeternia.dns/` |
| Собственная служба | `/Library/LaunchDaemons/space.aeternia.dns.plist` |
| Правило sudo | `/etc/sudoers.d/aeternia-dns-helper` |
| Серверы пользователя | `~/Library/Application Support/Aeternia DNS/servers.json` |

Код помощника и DNS-движок принадлежат root. DNS-движок копируется при установке;
его последующее обновление в Homebrew не обновляет эту копию — повторите установку.
Установщик отклоняет DNS-движок, связанный с несистемными динамическими библиотеками.

Разрешено выполнение одного фиксированного помощника без аргументов. JSON-запрос
проверяется по закрытому списку операций и параметров; пути, команды, произвольный TOML
и адреса серверов от интерфейса не принимаются. Поддерживаются восемь стран и Aeternia ID.
Помощник не умеет обновлять себя, запускать произвольный Python или shell.
Изменение/удаление программы требует нового подтверждения администратора.
Операции защищены блокировкой от одновременных запусков.

## Удаление

```bash
aeternia-dns-switcher --uninstall
```

Для удаления потребуется пароль администратора. Сначала восстанавливаются DNS,
затем удаляются служба, помощник, его правило, копия движка, системные данные и приложение.
Если восстановление не удалось, удаление прекращается, чтобы оставить способ повторить его.

Если интерфейс не запускается:

```bash
sudo /usr/bin/python3 -I -S /Library/PrivilegedHelperTools/space.aeternia.dns/macos_install.py --uninstall
```

Пользовательские серверы и старые файлы 2.1.3 сохраняются; при необходимости удалите
`~/Library/Application Support/Aeternia DNS`, старый `~/.config/aeternia-dns`
и старые резервные копии после проверки интернета.

## Проверка и ограничения этой сборки

Автоматические проверки выполняются командой:

```bash
python3 -m unittest discover -s tests -v
bash -n install.sh
bash -n build_installer.sh
bash -n aeternia-dns-installer.sh
```

Тесты имитируют macOS-команды: DHCP/ручные IPv4+IPv6 DNS, несколько подключений,
переименование, отсутствие маршрута, повторное отключение, частичное восстановление,
ошибки записи/очистки кэша/остановки, недоступный сервер, откат, фильтрацию входных данных.

Сборка подготовлена в Windows. Запуск установщика, `visudo`, `launchd`, системного
Python и реальные DNS-переключения на macOS **ещё не проверены**.
Перед публикацией выполните на Mac:

1. Установить сборку; проверить открытие приложения без пароля после `sudo -k`.
2. Записать вывод `networksetup -getdnsservers "Wi-Fi"`.
3. Включить страну, открыть сайт, выбрать «Без прокси», сразу открыть сайт снова.
4. Сравнить DNS с пунктом 2; повторить с ручными DNS и Ethernet.
5. Проверить повторное отключение, недоступный Aeternia-сервер, переименование подключения.
6. Перезапустить приложение с активным DNS и отключить его; убедиться, что сохранённые DNS вернулись.
7. Удалить программу с активным DNS и убедиться, что интернет работает.

Изменения подготовлены на базе коммита `86668694d6134d22a85a8508eaed28210c8b55f0`.
Перед установкой убедитесь, что скачали версию 2.2.0 или новее.
Наличие исходников в GitHub не заменяет проверку установщика и сети на настоящем Mac.
